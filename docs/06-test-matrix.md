# Multi-Monitor Test Matrix

This matrix documents the verification scenarios for Adaptive Dock's Per-Monitor Isolation architecture.

| Scenario | Expected Behavior | Expected OSD Location | Expected Persisted State Change | Actual Result |
|---|---|---|---|---|
| **Single Monitor Setup** | Extension behaves identically to legacy operation; rules saved under primary connector; no UI anomalies. | Displayed on the single active monitor (index 0). | Written to `dock-monitor-app-states.json` under primary connector; fallback file updated if configured. | Passed (Verified on single display). |
| **Dual Monitor Setup** | Monitors act as independent control domains. Focusing window on Monitor 2 evaluates Monitor 2 policy without altering Monitor 1's dock. | Displayed exclusively on the focused monitor. | Rules segregated under respective connector keys (`eDP-1` vs `DVI-I-2`). | Passed (Verified on live dual-monitor Wayland hardware). |
| **Hotplug Add (New Display Connected)** | `monitors-changed` event fires; connector cache refreshes; new display initialized with default or migrated rules; no crash. | No spurious OSD on hotplug; OSD appears on new screen upon interaction. | New connector key added to in-memory maps; disk records created on user mutation. | Passed (Verified cache rebuild and signal handling). |
| **Hotplug Remove (Display Disconnected)** | `monitors-changed` fires; cache rebuilds; active display remains stable; in-memory transient session maps for removed display are cleanly pruned. | OSD remains functional on surviving displays; never targeted to dead monitor. | Transient session maps pruned; disk records preserved for reconnection. | Passed (Verified cache resynchronization & pruning logic). |
| **Shortcut `<Shift><Super>D` on Monitor 2** | Resolves focused window on Monitor 2; toggles dock visibility state for that window/app on Monitor 2 only. | Rendered exclusively on Monitor 2 (`Main.osdWindowManager.show(1, ...)`). | Mutates Monitor 2 session/persistent rule; Monitor 1 rule is untouched. | Passed (Verified monitor scoping and targeted OSD). |
| **Shortcut `<Shift><Super>W` on Monitor 2** | Toggles workspace baseline for the active workspace on Monitor 2 only. | Rendered exclusively on Monitor 2. | Mutates Monitor 2 workspace state file in `dock-workspace-states/<connector>/`. | Passed (Verified workspace isolation). |
| **Workspace Switch on Monitor 2** | `active-workspace-changed` re-evaluates dock policy for Monitor 2. Monitor 1 dock state is preserved. | No OSD on quiet switch (or scoped to Monitor 2 if toggled). | Reads from `dock-workspace-states/<connector-2>/`. | Passed (Verified workspace switch scoping). |
| **Flag Disabled (`per-monitor-isolation: false`)** | Hard backward compatibility: state changes apply globally; OSD broadcasts to all screens; reads/writes flat legacy files. | Broadcast to all monitors simultaneously (`show(-1, ...)`). | Modifies root `dock-app-states.json` and `dock-workspace-states/*.state`. | Passed (Verified identical byte-for-byte legacy behavior). |
| **`focus_window` is null (Desktop / Empty Workspace)** | Falls back gracefully to `global.display.get_current_monitor()`; resolves pointer display; applies workspace baseline. | Rendered on pointer monitor if shortcut triggered; zero crash. | No spurious app rules created; workspace state respected. | Passed (Verified null-window pointer fallback). |
| **Primary Monitor Changed** | State remains tied to physical connector string (`eDP-1`), not the primary designation. Re-evaluates smoothly. | OSD appears on whatever monitor triggers the change. | Rules remain keyed to connector string. | Passed (Connector-based stability verified). |
| **Connector Resolution Failure** | Emits debug warning; gracefully falls back to `primaryIndex` -> `0` -> suppression; shell never crashes. | Falls back to primary monitor OSD. | State stored under safe fallback key (`'default'`). | Passed (Verified resilient fallback cascade). |
| **Rapid Focus Cycling Across Monitors** | Cache key `${connector}:${wsIndex}:${id}` ensures distinct evaluation; debounced / idempotent; no race condition or flicker. | OSD cancels previous and updates correctly. | State machine remains consistent; memory stable. | Passed (Verified re-entrancy and debounce safety). |
